# Bank distress & manipulation screener (Altman Z'' + Beneish M + ML)

Built from your workbook `Literature_Review_Research_Gap_with_Bank_Model.xlsx` and the two reference papers
(Sahoo & Behera 2025, Yes Bank; Parikh 2024, pharma Z + M).

## What is "the model"?

| Layer | File | What it is |
|---|---|---|
| Scores | `bank_risk/scoring.py` | **Exact formulas**: bank-adapted Altman Z''-EM, Beneish M (bank-mapped), Boyd-Graham Z. Reproduces the workbook's `Ratios` tab to ~1e-15 (`tests/test_parity.py`). Not trained, because Z and M are published closed-form formulas. |
| ML | `bank_risk/ml.py` | **Isolation Forest** anomaly model (unsupervised) + **logistic early-warning model** (supervised, label = distress event within 1 FY, from `data/events.csv`) + transparent **risk-tier rules**. |
| Validation | `ml.event_validation` | TP/FP/FN/TN and AUC of every signal against the Yes Bank event (workbook gap G4). |
| API | `api.py` | FastAPI back-end for the website. |

## Quick start

```bash
pip install -r requirements.txt
python train.py                      # scores panel, trains ML, writes models/ and outputs/
python tests/test_parity.py          # engine == workbook
uvicorn api:app --reload --port 8000 # docs at http://localhost:8000/docs
jupyter notebook notebooks/bank_risk_model.ipynb
```

If `models/risk_models.joblib` was built with a different scikit-learn version, just run `python train.py` again.

## API (for the website)

```bash
curl -X POST localhost:8000/score -H "Content-Type: application/json" -d '{
  "rows": [ {"bank":"Yes Bank","fy":"FY2019","total_assets":380826, ...}, {"bank":"Yes Bank","fy":"FY2020", ...} ],
  "options": {"neutral_fill": false}
}'
```
```js
// front-end
const r = await fetch("http://localhost:8000/score/upload", {method:"POST", body: formData}); // CSV or XLSX
const {results, warnings} = await r.json();
```

* `GET /schema` lists required vs optional columns; `GET /template.csv` gives a ready CSV template.
* Column names may be snake_case (`total_assets`) **or** your original workbook headers (`Total assets`).
* Each result has `z_em, z_zone, m_score, m_flag_a/b, joint_signal, anomaly_percentile, early_warning_prob, risk_tier, input_notes`, plus every component ratio so the UI can show the working.
* **Send at least 2 consecutive years per bank** (Beneish compares with the prior year); 3 for Boyd-Graham.

## Variable mapping (assumptions you should state in the write-up)

* Z'' X1 = (cash + investments - borrowings - other liabilities) / total assets; X2 = reserves / TA; X3 = PBT / TA; X4 = market cap / total liabilities; +3.25 EM constant; Safe > 5.85, Distress < 4.35.
* Beneish: sales = total income; COGS = interest expense; receivables = net (else gross) advances; AQI via 1 - earning assets/TA; DEPI = dep/(dep + fixed assets); LVGI = liabilities/TA; TATA = (net profit - operating cash flow)/TA.
* If a column is missing the engine derives it and says so in `input_notes` (e.g. PBT = net profit / (1 - 25%)).

## Limitations (read before showing results)

1. **Much of the input data is estimated** (`n_estimated_fields`, workbook `Estimate_Log`; FY2025-26 are projections). Scores demonstrate the method, not audited findings.
2. **One distressed bank.** The early-warning model cannot be validated; leave-one-bank-out removes every positive. Add more labelled events to `data/events.csv` (and more banks to `data/bank_panel.csv`) and retrain.
3. **Z'' zones over-trigger on banks** (Axis, IDFC First are flagged "Distress" in some years); Z'' *ranks* Yes Bank FY2020 clearly lowest. **Beneish M is weak on banks**: no bank-year exceeds -1.78.
4. Merger years (HDFC Bank FY2024, IDFC First FY2019) are tagged `structural_break`; M indices are not comparable across a merger.
5. `risk_tier` rules are hand-written, not learned. They are in `ml.assign_risk_tier` and easy to change.
